# Фотоархив

`cloudphoto` — консольная программа для управления фотоальбомами в Yandex Object Storage. Фотографии и страницы статического сайта хранятся в одном бакете.

Программа поддерживает просмотр альбомов, загрузку, скачивание и удаление фотографий, а также публикацию сайта командой `mksite`.

Для сборки нужен Go. Сдаваемая сборка предназначена для Linux x86_64. Инфраструктура описывается в директории `terraform`; для неё нужен Terraform и настроенный профиль Yandex Cloud CLI.

## Инфраструктура

На Mac установите GnuPG и настройте `yc`. Затем подготовьте локальное шифрование и параметры:

```bash
python3 scripts/keyring.py
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
bash scripts/infra.sh init
bash scripts/infra.sh validate
bash scripts/infra.sh plan
bash scripts/infra.sh apply
```

В примере параметры каталога vvot05: для другого студента измените пять значений в локальном `terraform.tfvars`. В условии переменная `dns_zone_id` описана как полное имя сайта, поэтому здесь она содержит `photos.vvotNN.itiscl.ru`. Настоящий ID существующей зоны находится по её имени `vvotNN`, принятому в предварительной лабораторной. `domain` содержит `vvotNN.itiscl.ru`, а `bucket_name` совпадает с полным адресом сайта.

Скрипт получает IAM-токен через `yc iam create-token` и экспортирует его только для Terraform. Он не показывает сырые ответы API. Сервисный аккаунт получает права только на созданный бакет. Секретная часть его S3-ключа шифруется PGP до сохранения в state; пароль локального PGP-ключа хранится в связке ключей macOS. Каталог ключей находится вне репозитория. State, реальные параметры и файлы `.local` нельзя публиковать.

Terraform создаёт бакет, DNS-запись, настройку HTTPS, сервисный аккаунт и ключ. Публичное чтение объектов и хостинг настраивает `cloudphoto mksite`; последующий `apply` не отменяет эти настройки. Существующие зона DNS и сертификат используются без пересоздания.
