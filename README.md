# Фотоархив

`cloudphoto` — консольная программа для управления фотоальбомами в Yandex Object Storage. Фотографии и страницы статического сайта хранятся в одном бакете.

Программа поддерживает просмотр альбомов, загрузку, скачивание и удаление фотографий, а также публикацию сайта командой `mksite`.

## Сборка

Для сборки нужен Go 1.24 или новее и `make`:

```bash
make build
```

Результат — `dist/linux-amd64/cloudphoto`, статический исполняемый файл для Linux x86_64. Go и Python для его запуска не нужны. Разработка и сборка выполняются на Mac, запуск проверок — в Ubuntu.

## Настройка программы

Программа читает только три переменные окружения:

| Переменная | Назначение |
|---|---|
| `BUCKET` | Имя бакета фотоархива, совпадающее с `bucket_name` Terraform |
| `AWS_ACCESS_KEY_ID` | Идентификатор статического S3-ключа сервисного аккаунта |
| `AWS_SECRET_ACCESS_KEY` | Секретная часть этого ключа |

Регион `ru-central1` и endpoint `https://storage.yandexcloud.net` заданы в коде. Конфигурационные файлы AWS, профили и автоматически найденные учётные данные не используются.

Ключи не следует вводить прямо в команду `export`, записывать в файлы проекта или печатать в терминал. Например, в Bash их можно ввести скрыто:

```bash
export BUCKET=photos.vvot05.itiscl.ru
read -r -s -p 'AWS_ACCESS_KEY_ID: ' AWS_ACCESS_KEY_ID; printf '\n'
read -r -s -p 'AWS_SECRET_ACCESS_KEY: ' AWS_SECRET_ACCESS_KEY; printf '\n'
export AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
```

После работы удалите переменные из текущей оболочки:

```bash
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
```

Это очищает окружение, но не отзывает ключ на стороне сервиса. IAM-токен Terraform программе не нужен.

## Команды

```bash
cloudphoto list
cloudphoto list --album 'Природа'
cloudphoto upload --album 'Природа' --path ./photo/nature
cloudphoto download --album 'Природа' --path ./download
cloudphoto delete --album 'Природа' --photo 'Лес.JPG'
cloudphoto delete --album 'Природа'
cloudphoto mksite
```

Если `--path` отсутствует, используется текущая директория. Программа не обходит вложенные директории и загружает только обычные файлы с расширениями `.jpg` и `.jpeg`, без учёта регистра расширения. Символьная ссылка с таким расширением приводит к ошибке.

Имена альбомов и файлов сохраняются с учётом регистра, без Unicode-нормализации и обрезки пробелов. `list` сортирует строки по байтам UTF-8. Пустой архив или пустой альбом даёт пустой вывод. Имена не могут содержать `/`; специальные символы, кириллица и пробелы поддерживаются. CR/LF сохраняются буквально, поэтому вывод таких имён нельзя однозначно разбирать построчно.

Повторный `upload` заменяет файл с точно совпавшим именем в том же альбоме. `download` заменяет существующие файлы, записывая каждый сначала во временный файл: оборванная загрузка не повреждает старое содержимое. Удаление последней фотографии оставляет пустой альбом; `delete` без `--photo` удаляет и сам альбом.

Результаты выводятся в stdout, ошибки — в stderr. Код завершения: `0` при успехе, `1` при ошибке. Отсутствующие переменные дают `Не заданы переменные окружения`, некорректный запуск — `Ошибка в аргументах`. Операции над несколькими файлами не являются общей транзакцией: при ошибке уже завершённые действия сохраняются, а команда возвращает `1`.

## Организация хранилища

```text
albums/<имя альбома в hex-кодировке UTF-8>/.album
albums/<имя альбома в hex-кодировке UTF-8>/photos/<исходное имя файла>
index.html
error.html
album1.html ... albumN.html
```

Например, альбом `A` кодируется как `41`, а его фотография `Лес.JPG` имеет ключ `albums/41/photos/Лес.JPG`. Hex-кодирование обратимо, сохраняет регистр и порядок байтов, исключает конфликт имени альбома с разделителями ключа. Исходные имена фотографий не изменяются.

Пустой объект `.album` обозначает существование альбома независимо от числа фотографий. Одинаковые имена в разных альбомах имеют разные ключи. Служебные страницы лежат отдельно от `albums/` и не появляются в списках фотографий. При удалении альбома программа удаляет его фотографии, затем маркер; неизвестные служебные объекты не затрагиваются.

Команды обрабатывают все страницы списка S3. Пакетное удаление разбивается на группы по 1000 объектов; ошибки отдельных объектов не игнорируются. Длина ключей проверяется в байтах с учётом ограничения Object Storage.

## Публикация сайта

`mksite` включает публичное чтение объектов через bucket policy и настраивает хостинг с `index.html` и `error.html`. Анонимные запись, удаление, просмотр списка объектов и чтение конфигурации не разрешаются.

Команда читает существующую политику и сохраняет её правила, включая доступ администратора Terraform. Обновляются три собственных правила: публичное чтение, управление по текущему статическому ключу через `yc:access-key-id` и доступ облачной консоли через `aws:PrincipalIsAWSService`. У Яндекса политика работает как белый список: правило только с публичным `GetObject` заблокировало бы последующие команды. При ротации ключа сначала обновите разрешение в политике через администратора инфраструктуры.

Альбомы сортируются по байтам UTF-8 и получают страницы `album1.html`, `album2.html` и далее. Программа использует шаблоны задания, включая Galleria 1.6.1 и jQuery 3.6.0. Имена экранируются для HTML, сегменты URL фотографий кодируются отдельно. Главная страница загружается после страниц альбомов; повторный вызов обновляет сайт. После upload/delete нужно снова выполнить `mksite`.

Старые страницы `albumN.html`, переставшие входить в текущую нумерацию, не удаляются автоматически; новая главная на них не ссылается. Одновременные изменения архива во время генерации сайта не поддерживаются как транзакция.

Адрес сайта для приведённых параметров: `https://photos.vvot05.itiscl.ru/`. HTTPS включается настройкой бакета с сертификатом Certificate Manager; распространение этой настройки может занимать до получаса.

## Инфраструктура

На Mac установите GnuPG и настройте `yc`. Затем подготовьте локальное шифрование и параметры:

```bash
python3 scripts/keyring.py
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
bash scripts/infra.sh init
bash scripts/infra.sh validate
bash scripts/infra.sh plan
bash scripts/infra.sh apply
```

В примере параметры каталога vvot05: для другого студента измените пять значений в локальном `terraform.tfvars`. В условии переменная `dns_zone_id` описана как полное имя сайта, поэтому здесь она содержит `photos.vvotNN.itiscl.ru`. Настоящий ID существующей зоны находится по её имени `vvotNN`, принятому в предварительной лабораторной. `domain` содержит `vvotNN.itiscl.ru`, а `bucket_name` совпадает с полным адресом сайта.

Скрипт получает IAM-токен через `yc iam create-token` и экспортирует его только для Terraform. Он не показывает сырые ответы API. Сервисный аккаунт получает права только на созданный бакет. Секретная часть его S3-ключа шифруется PGP до сохранения в state; пароль локального PGP-ключа хранится в связке ключей macOS. Каталог ключей находится вне репозитория. State, реальные параметры и файлы `.local` нельзя публиковать.

Terraform создаёт бакет, DNS-запись, настройку HTTPS, сервисный аккаунт и ключ. Публичное чтение объектов и хостинг настраивает `cloudphoto mksite`; последующий `apply` не отменяет эти настройки. Существующие зона DNS и сертификат используются без пересоздания.

При `infra.sh init` команда `yc iam whoami` определяет текущего администратора и сохраняет только его идентификатор в локальный `.local/administrator.json`. Terraform использует его в начальной политике бакета; `mksite` сохраняет это правило. IAM-токен в этот файл и state не записывается.

`make fmt` форматирует Go и HCL, `make vet` выполняет статическую проверку Go для целевой платформы. Не включайте `TF_LOG`, трассировку shell или SDK с реальными ключами. Скрипт `infra.sh apply` применяет сохранённый ранее план, не создавая ресурсы повторно вслепую после тайм-аута.

## Проверки в Ubuntu

Стенд: Multipass `claudlab`. Для запуска x86_64-файла на ARM64 Ubuntu установите QEMU:

```bash
multipass exec claudlab -- sudo apt-get update
multipass exec claudlab -- sudo apt-get install -y qemu-user
make test
```

`make test` собирает исполняемые файлы тестов на Mac, копирует их и приложение в Ubuntu, запускает через `qemu-x86_64`. Исходники и Go-компилятор гостевой системе не требуются. Проверки покрывают аргументы и окружение, все операции архива, сортировку, частичные ошибки, безопасное скачивание, HTML/URL, пагинацию и пакетное удаление S3. Они используют фиктивные ключи и локальный тестовый HTTP-сервер внутри Ubuntu.

Для сквозной проверки с настоящим хранилищем подготовьте любой JPEG-файл `photo.jpg` и скопируйте его со сценарием в Ubuntu:

```bash
multipass transfer tests/client_checks.py claudlab:/home/ubuntu/cloudphoto-test/client_checks.py
multipass transfer ./photo.jpg claudlab:/home/ubuntu/cloudphoto-test/fixture.jpg
python3 scripts/client_checks.py
```

Последняя команда запрашивает ключи скрытым вводом. Если инфраструктура создавалась из этого проекта на том же Mac, вместо ввода можно явно выбрать расшифровку локального Terraform state:

```bash
python3 scripts/client_checks.py --from-state
```

Этот самостоятельный запуск получает пароль PGP из macOS Keychain, расшифровывает S3-ключ только в память и передаёт его через stdin тестовому процессу Ubuntu. IAM-токен и приватный PGP-ключ в гостевую систему не передаются. Процесс запускает приложение с минимальным окружением, не сохраняет значения credentials и завершает работу после проверок.

Сценарий создаёт отдельные временные альбомы, проверяет реальные upload/list/download/delete/mksite, SHA-256 скачанных файлов, HTTPS и запрет анонимных изменений. Тестовые альбомы удаляются адресно; существующие пользовательские альбомы не очищаются. Отчёт без секретов сохраняется в `/home/ubuntu/cloudphoto-test/client-result.json`.
